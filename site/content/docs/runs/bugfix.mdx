## What to notice

- **Repro first, as asked.** Both runs printed the example invoice and did the arithmetic (5997 cents times 15% is 899.55) before touching code. Both confirmed the subtotal was an exact 5997 cents, which ruled out a float error and left the rounding as the cause.
- **A failing test, then the fix.** Both put the test in its own commit on a branch and the one-word fix (`Math.floor` to `Math.round`) on top. The plain run's test pins all four totals. The berth run's test checks only the discount and the total.
- **It read only the principles it cited.** Fix Root Causes, Sequence Work into Verifiable Units and Test Behavior, Not Implementation, then named each one with the choice it changed.
- **No todo list.** Headless `claude -p` has no todo tool, so neither run opened the playbook's checklist the way the skill asks. The skipped steps show up in the reply instead, each with a reason.
- **Small and cheap.** No subagents and no `/how` for a one-function fix: $0.40 and under a minute each. Both left the "Totall" typo alone to keep the change focused, and the berth run flagged a real rounding-policy decision for you.
