title: Getting started

**What it does.** Installs the skills, sets your models, and runs a first task.

**Why.** The defaults work. `/setup-shipit` only matters when you want to trade cost against quality, or let auto mode trust your repos.

1. **Install.** Needs Claude Code; `gh`, `bun`, `codex` and [berth](/berth) are optional.

   ```sh
   git clone https://github.com/sean-brydon/shipstack ~/shipstack
   cd ~/shipstack && ./install.sh
   ```

   It links the skills into `~/.claude/skills/` and two agents into `~/.claude/agents/`, so a `git pull` updates them. `--dry-run` previews; `--uninstall` removes only its links.

2. **Run `/setup-shipit`** (optional). It detects `codex` and berth, asks for a budget (`unlimited`, `large` by default, `medium`, `small`), confirms the model per role, names your GitHub repos for auto mode, and writes `~/.claude/shipit/models.md`.

3. **Give it a first task, and say what done means.** The todo list opens with the matched playbook's steps.

   ```text
   /shipit add a --json flag to this command. text output stays byte-identical. verify both.
   ```

   `/shipit` applies to the message it is on. Say "stay in shipit mode for the rest of this session" to keep it on. Not sure which skill fits? Ask `/shipit-help`.

**Auto mode.** Run `/shipit` in Claude Code's auto permission mode, or every check, commit and subagent can stop at a prompt. Irreversible actions still pause in any mode. See [Auto mode](/auto-mode).
