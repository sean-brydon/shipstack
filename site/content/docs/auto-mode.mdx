---
title: Auto mode
description: What auto mode blocks, how /shipit behaves when a call is denied, and the one setting worth adding.
---

**What it does.** Lets `/shipit` run long without stopping at permission prompts, and treats a denied call as an answer.

**Why.** Without auto mode every check, commit and subagent can wait on a prompt, and an overnight run sits until you wake up.

**What auto mode blocks:** force push, `git reset --hard`, `git checkout -- .`, `git clean -fd`, `git stash drop`, production deploys and migrations, mass cloud deletion, IAM and secret writes, merging unapproved PRs, piping curl to a shell, sending sensitive data out, and adding a git remote you didn't name. Pushes and PRs to the working repo are allowed.

When a call is denied, `/shipit`:

1. **Takes it as an answer.** It logs the block, skips or stops the step, and reports the reason. It never retries or routes around it. Three denials in a row pause the run.
2. **Prefers reversible forms:** `git stash` over `git checkout -- .`, a new commit over a reset, `--force-with-lease` only on its own branch.
3. **States intent first.** The classifier reads messages, not tool output, so "pushing fix/scroll-drift to open the PR" goes before the push.
4. **Merges only what you approved** in a message.

Force-pushing a shared branch, deploys, deleting data, publishing and messaging people always pause, in any mode.

**Name your repos.** `/setup-shipit` sets `autoMode.environment` in `~/.claude/settings.json` to the GitHub owners and repos you push to, so pushes and PRs there read as trusted. It shows a `--dry-run` first, writes only on your go, and keeps a backup. Check it with `claude auto-mode config`.
