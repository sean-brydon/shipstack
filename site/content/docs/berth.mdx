title: berth
description: What berth (Shipyard) adds to shipstack, and what every step does without it.
---

**What it does.** [berth](https://github.com/cosscom/shipyard) (Shipyard) runs coding agents on your own machines. shipstack uses it when it finds a `BERTH_*` variable, `berthd` or `berth` on the `PATH`, or the `mcp__berth__*` tools.

**Why.** Parallel attempts need their own worktree, port and environment, and long work needs a box that outlives your laptop. Every berth step has a plain Claude Code fallback, so berth is never required.

| step | with berth | without berth |
|---|---|---|
| parallel attempts and code delegates | a berth task each, with its own worktree, port and env | an Agent subagent with `isolation: "worktree"` |
| knowing a delegate finished | a `<berth-notification>` | the Agent tool's completion notice |
| driving a page | **berth-browser** on the worktree's dev server | **claude-in-chrome** or the project's Playwright |
| before and after screenshots | **berth-visual-diff**, phone to desktop, with a heatmap | paired screenshots |
| numbers, tables, plans | **berth-artifacts**, live in Shipyard | the `Artifact` tool or a markdown table |
| a second vendor in a panel | a berth task with `--agent codex` | `codex exec`, read-only |
| work that outlives your laptop | a berth task on a box | the session stays open |

The switch in the sidebar shows every page's examples with or without berth. It changes what you read, not what the skills do.
