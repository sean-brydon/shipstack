The proof pack is the evidence that a change works. It is for a reader who won't run anything: they look at it and believe the claim, or they see exactly where it falls short. `/shipit` builds it before it says done and before it opens a PR.

## Size it to the change

| change | proof |
|---|---|
| a nit: typo, copy, config value, comment, dependency bump | the one check that covers it, with its command and result |
| backend: logic, API, data, CLI | the repo's checks plus one real run of the changed path (a test that hits it, a request and its response, a CLI run, a log line) |
| anything that shows on a screen | screenshots in light and dark, and the visual diff |
| a number | a chart of before and after with its command |
| docs only | the docs build, or the rendered page |

A one-line Proof section is fine when one line is the honest proof. "Nothing to prove: README wording only" is fine too, when true. The point is that proof is stated on purpose.

## What goes in it

Every row that applies to the change goes in. A row that applies but can't be produced stays in the pack as a gap, with the reason.

`/create-verification-skill` makes a project verify skill when your app has none.

## Rules

- **Real artifact, not a proxy.** Screenshot the running app, not a story or a mock. Measure the real path, not a microbenchmark of a helper.
- **Look at every shot before using it.** A screenshot of a spinner, an error page, the wrong theme or a cropped-off change is not proof. Retake it.
- **Every item names its source.** The command, the URL and port, the commit. A reader can rerun it.
- **Score UI against the bar.** UI proof includes the Design audit's last score: 8 out of 10 or better, or the honest number and why.
- **Gaps are listed, not hidden.** "Not verified on Windows: no box available" is fine. Silence is not.

## In the PR

The PR body gets a **Proof** section: the screenshots embedded in light and dark, the visual-diff summary, charts as images or links, and a table of checks with their command and result. `gh` can't upload images, so they go on a `pr-assets` branch (one folder per PR, never merged) and are embedded by their GitHub URL. Screenshots don't go into the feature branch unless the repo does that.

## Enforce it with a hook

`skills/shipit/hooks/require-proof.py` is a Claude Code `PreToolUse` hook. It refuses `gh pr create` when the PR body has no `## Proof` section with something under it. One line is enough for a nit. It is off until you add it to `~/.claude/settings.json` under `hooks`:

```json
"PreToolUse": [
  { "matcher": "Bash", "hooks": [ { "type": "command", "command": "python3 -I ~/.claude/skills/shipit/hooks/require-proof.py" } ] }
]
```

Its test cases run with:

```sh
python3 -I skills/shipit/hooks/require-proof.test.py
```
