---
title: "Worktree and simulator cleanup"
description: "Reclaim disk by pruning merged or abandoned worktrees, safety-gated."
---

1. Snapshot and audit. Record `df -h /`, then run `~/.claude/skills/shipit/scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (the **Build the Lever** principle). Run it where the worktrees live. That is the laptop for local worktrees, and the box (from an agent or shell there) for berth's. Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.claude/worktrees/x` (where the Agent tool's `isolation: "worktree"` puts them) or at a berth sibling like `myrepo-x` (the **Encode Lessons in Structure** principle). It classifies each worktree by size, age, merge state, uncommitted work, PR state, berth ownership (the `BERTH` column, `<loc>/<name>` when `berthd` manages it), and the newest Claude Code chat that touched it (`LAST_CHAT`, date and session id prefix, from `~/.claude/projects/`), then suggests a bucket. The transcript scan is slow, so run it as a background Bash command.
2. The bucket is advice, not permission. The live chats are the real artifact (the **Prove It Works** principle). Get that set from the user, from `berthd sessions --json` (each live session's `dir`), and from processes still running inside a candidate (`lsof -d cwd -Fn`, matched against its path), then cross-check every candidate. The lever has marked `safe` a worktree a live chat was using, so the live set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan `Explore` subagents out to read the transcripts and report whether the chat is still in use and which worktrees it touches (the **Guard the Context Window** principle, because transcripts are bulk). A live chat spawns arena and repro trees into sibling worktrees through background subagents and berth tasks, and those are in use even when their names never show in the chat. Pick each subagent's model and `effort` for the job, per the Subagents section of [`~/.claude/skills/shipit/SKILL.md`](/skills/shipit).
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. `hold-berth-session` means a berth session still runs in it, so it is in use. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. A berth-managed worktree (the `BERTH` column names it) goes through berth, so its location's archive script runs (dropping a per-worktree database, say) and berth forgets it. Run `berthd worktree rm <loc>/<name>` on the box, or `berth worktree rm <box>/<loc>/<name>` from the laptop. Pass `--force` only for a worktree step 4 cleared. If a `before:` hook refuses the removal, respect it and report its reason. Never delete berth's own state (`~/.berth`, berth's config and state directories on a box) to reclaim space. Every other worktree goes through plain git. Per clean path, `git worktree remove <path>`, then `git worktree prune`. Never `rm -rf` a worktree directory. Anything that isn't a clean worktree (git refuses the removal, untracked or ignored files remain, a lock, a stray directory) gets listed with what is left in it, and you pause for the user's go. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list (`git worktree list`, and `berthd locations --json` for berth's).
6. Simulators and other reclaimers. Before any deletion in this step, show the list with sizes (`xcrun simctl list`, `xcrun simctl runtime list`, `du -sh` per cache) and get the user's go. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, and package caches (pnpm, uv, brew, yarn). On a box, `berthd stats` shows its disk. Clear only caches the user has not said to keep. Claude Code transcripts under `~/.claude/projects/` are the user's history, not a cache.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Evidence.** The audit is a table. Keep it as one (the **berth-artifacts** skill, the audit's TSV with a `status` column added for pruned, held, or kept; outside berth, a markdown table) and add a before-and-after disk bar (`df -h /` used space) when the reclaim is large.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned (and whether through berth or git), and a one-line reason for each held back (in use by which chat or berth session, or uncommitted work).
