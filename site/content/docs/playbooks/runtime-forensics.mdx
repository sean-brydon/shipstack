**What it does.** Diagnoses a live symptom (leak, idle CPU, glitch) by instrumenting the running process. The deliverable is a cited diagnosis, not a fix.

**Say something like.** "memory leak", "idle CPU", "it glitches every few seconds"

<details className="ss-full">
<summary>Full instructions (what the agent reads)</summary>

**You own the diagnosis. Instrument the live process, don't theorize from source.** The deliverable is a cited diagnosis, not a fix.

1. Capture the live signal on the matching surface (Non-negotiables): a CPU profile for a spinning process, a heap snapshot for a leak, a CDP trace for a visual glitch. A real artifact, not a guess. For a page, drive the real surface and read its console, network and page state (see your adapter). For a CLI or server, drive it from the shell or a terminal multiplexer and attach the runtime's own profiler.
2. Reduce the artifact to the smoking gun: the function on the hot path, the retainer chain from the leaked object to a GC root, the loop firing without input. Parse large artifacts in a read-only helper (the **Guard the Context Window** principle, [`principles/guard-the-context-window.md`](/principles/guard-the-context-window)), keep the reduced finding in the main thread. Pick each helper's effort for the job, per the router's Subagents section.
3. Prove the mechanism before believing it. Inject instrumentation via CDP eval on the running process, or hotfix the live code without reloading, to confirm the hypothesis cheaply.
4. Map the finding back to source: file, symbol, the line that allocates or schedules.
5. Show the reduced finding, not the raw dump. A table of the top frames (self time, total time, source location), a retainer chain or a firing loop as a Mermaid flowchart, or a line chart of heap size or CPU over time when the signal is a trend. Publish it as an artifact when you can, else a markdown table or Mermaid block in the reply. Name the capture it came from.
6. Throughput checkpoint stays one line: `throughput checkpoint: n/a, read-only forensics`.

**Reply:** the signal captured, the reduced finding with its table or diagram, how you proved the mechanism, the source location, artifact paths. No fix unless asked. Hand back to Bug fix or Perf once the cause is known.
