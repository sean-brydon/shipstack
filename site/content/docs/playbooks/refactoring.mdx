**What it does.** Changes the structure of code while its behavior stays identical.

**Say something like.** "move/extract/rename …", "zero behavior change"

<details className="ss-full">
<summary>Full instructions (what the agent reads)</summary>

**You own the contract. The structure changes. The behavior does not.** Distinct from Feature, which adds behavior, and Bug fix, which corrects it.

If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to Feature. Large or cross-cutting structural work belongs to the **figure-it-out** skill (`<skills>/figure-it-out/SKILL.md`). This playbook is the focused-to-medium change.

1. Pin the behavior contract first. Run the **how** skill (`<skills>/how/SKILL.md`) over the affected subsystem to learn the contract, then write a characterization test, snapshot, or equivalence harness that captures current behavior before any structure moves. If the area has no coverage, write the pin before touching structure. Type check and lint are not a pin. When the code renders a page, add a visual pin too. Save a named screenshot baseline (for example `pre-refactor`) at phone, tablet, and desktop widths before you move anything. See your adapter for the tool.
2. Name the structure the code is missing per the **Model the Domain** principle ([`principles/model-the-domain.md`](/principles/model-the-domain)). Boring code stays when the shape is already clear and local. The reshape must delete branches or invalid states, not add indirection.
3. Name the target shape. State what the module layout, types, and call graph should be if built today (the **Foundational Thinking** principle, [`principles/foundational-thinking.md`](/principles/foundational-thinking), and the **Redesign from First Principles** principle, [`principles/redesign-from-first-principles.md`](/principles/redesign-from-first-principles)). If the target crosses a function boundary, run the **architect** skill (`<skills>/architect/SKILL.md`) for parallel design exploration of the shape before the move.
4. Subtract before you add. Delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape (the **Subtract Before You Add** principle, [`principles/subtract-before-you-add.md`](/principles/subtract-before-you-add)). The smallest change that reaches the target shape ships (the **Laziness Protocol** principle, [`principles/laziness-protocol.md`](/principles/laziness-protocol)). A speculative cleanup that "might help" gets reverted.
5. Move in small behavior-preserving steps, each keeping the pin green. For API reshapes, migrate every caller and delete the old API in the same wave (the **Migrate Callers Then Delete Legacy APIs** principle, [`principles/migrate-callers-then-delete-legacy-apis.md`](/principles/migrate-callers-then-delete-legacy-apis)). No compatibility shims, no parallel old-and-new paths. Spot-check every rename against the actual files. Renames silently miss usages in strings, prose, and back-references. Delegate the mechanical edits to a writing helper in its own worktree, on the `code` role's model, with a specific scope (file paths, the names being moved, the behavior to hold). Pick each helper's effort for the job, per the router's Subagents section.
6. Prove behavior is unchanged on the real artifact, not "it compiles" (the **Prove It Works** principle, [`principles/prove-it-works.md`](/principles/prove-it-works)). For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface. For a page, a visual diff against the saved baseline must report no change at every size, and the user sees that diff. Otherwise screenshot the same pages before and after.
7. Confirm the change is worth keeping. The success measure is reduced reader load (the **Minimize Reader Load** principle, [`principles/minimize-reader-load.md`](/principles/minimize-reader-load)). Count it before and after: layers a reader crosses for the main path, one-caller wrappers, branches, mutable state, lines. Put the counts in a small table. If the diff does not lower reader load somewhere, revert it.
8. Rebase into small ordered commits. A subtraction commit, then the reshape, then any follow-on cleanup. Shape them with the **Sequence Work into Verifiable Units** principle ([`principles/sequence-verifiable-units.md`](/principles/sequence-verifiable-units)), so each behavior-preserving slice stays green before the next. Run **Opening a PR** ([`playbooks/opening-a-pr.md`](/playbooks/opening-a-pr)).

**Reply:** the structure that changed, the pin you held it against, the equivalence proof (the diff output, or the unchanged visual diff), the reader-load delta as the before and after table, what shipped and what got reverted. No new behavior.
