**What it does.** Reclaims disk by pruning merged or abandoned worktrees, after checking no live chat still uses them.

**Say something like.** "free up disk", "prune old worktrees"

<details className="ss-full">
<summary>Full instructions (what the agent reads)</summary>

1. Snapshot and audit. Record `df -h /`, then run `<skills>/shipit/scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (the **Build the Lever** principle). Run it where the worktrees live. That is the laptop for local worktrees, and the remote machine (from an agent or shell there) for an orchestration tool's. Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses a worktree an agent placed somewhere else, such as inside the repo's own agent folder or as a sibling like `myrepo-x` (the **Encode Lessons in Structure** principle). It classifies each worktree by size, age, merge state, uncommitted work, PR state, which orchestration tool manages it (the ownership column, `<loc>/<name>` when one does), and the newest agent chat that touched it (`LAST_CHAT`, date and session id prefix, from the session transcripts), then suggests a bucket. The transcript scan is slow, so run it as a background command.
2. The bucket is advice, not permission. The live chats are the real artifact (the **Prove It Works** principle). Get that set from the user, from your orchestration tool's list of live sessions and their directories if there is one (see your adapter), and from processes still running inside a candidate (`lsof -d cwd -Fn`, matched against its path), then cross-check every candidate. The lever has marked `safe` a worktree a live chat was using, so the live set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan read-only helpers out to read the transcripts and report whether the chat is still in use and which worktrees it touches (the **Guard the Context Window** principle, because transcripts are bulk). A live chat spawns arena and repro trees into sibling worktrees through background helpers and orchestrated tasks, and those are in use even when their names never show in the chat. Pick each helper's model and effort for the job, per the router's Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. `hold-berth-session` means an orchestrated session still runs in it, so it is in use. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. A worktree an orchestration tool manages (the ownership column names it) is removed through that tool, so its location's archive script runs (dropping a per-worktree database, say) and the tool forgets it. (berth: see the berth adapter.) Pass a force flag only for a worktree step 4 cleared. If a hook in that tool refuses the removal, respect it and report its reason. Never delete the tool's own state or config directories to reclaim space. Every other worktree goes through plain git. Per clean path, `git worktree remove <path>`, then `git worktree prune`. Never `rm -rf` a worktree directory. Anything that isn't a clean worktree (git refuses the removal, untracked or ignored files remain, a lock, a stray directory) gets listed with what is left in it, and you pause for the user's go. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list (`git worktree list`, and the orchestration tool's own location list if it has one).
6. Simulators and other reclaimers. Before any deletion in this step, show the list with sizes (`xcrun simctl list`, `xcrun simctl runtime list`, `du -sh` per cache) and get the user's go. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, and package caches (pnpm, uv, brew, yarn). On a remote machine, check its disk with its own tools. Clear only caches the user has not said to keep. Agent session transcripts are the user's history, not a cache.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Evidence.** The audit is a table. Keep it as one (the audit's TSV with a `status` column added for pruned, held, or kept, published as an artifact when you can, else a markdown table) and add a before-and-after disk bar (`df -h /` used space) when the reclaim is large.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned (and whether through an orchestration tool or git), and a one-line reason for each held back (in use by which chat or orchestrated session, or uncommitted work).
