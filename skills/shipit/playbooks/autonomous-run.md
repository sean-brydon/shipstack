### Autonomous run

**You own the exit condition. Define done, then drive to it without stopping.**

A long run assumes Claude Code's auto mode or a permission allowlist, so routine actions don't stop it. Irreversible actions (force-push to shared branches, deploys, data deletion, messages to customers, publishing) still pause for the human, whatever the mode.

1. State the exit condition as a checkable predicate before the first iteration (tests green, repro fixed, all N PRs merged, pixel-diff zero).
2. Pick the wake mechanism. An event to watch gets a watcher that wakes you on the event, and you end your turn until it does. CI or a PR on GitHub gets `gh pr checks <pr> --watch` or the `watch-pr` watcher (`~/.claude/skills/shipit/playbooks/babysit.md`) as a background Bash command (`run_in_background: true`), which notifies you when it exits. A stream of events (each CI check, each merge in a queue, each new error line) gets the `Monitor` tool. Work you started in berth (`berthd task new`, `berthd exec --detach`, `berthd run start`, the `berth_*` tools) reports back with a `<berth-notification>`, and an Agent tool subagent notifies on completion, so neither needs a watcher. Add Claude Code's `/loop` with a long interval as the time-based heartbeat fallback. No event gets a fixed-interval `/loop` heartbeat sized to when the result is worth re-checking. Pick each subagent's model and `effort` for the job, per the Subagents section of `~/.claude/skills/shipit/SKILL.md`.
3. Each iteration makes the smallest change the evidence justifies, verifies it against the predicate, commits if it advanced, discards changes that didn't help. Belt-and-suspenders that "might help" gets reverted, not left to ride.
   Sequence the work via the **Sequence Work into Verifiable Units** principle (`~/.claude/skills/shipit/principles/sequence-verifiable-units.md`), verifying each unit before the next instead of batching checks at the end.
4. Mid-run discoveries are yours. Address broken skills, related bugs, flaky verifiers, review noise, tooling failures, orphaned follow-ups, and fixable drift yourself via shipit. Put out-of-band fixes in their own PR. Do not park reversible work for the human or use `AskUserQuestion`. Surface only irreversible actions, genuine product or preference calls no experiment can settle, or a real dead end. Keep the predicate as the main drive, and return to it after each side fix.
5. Checkpoint every iteration via the **show-me-your-work** skill, a row for what changed and whether the predicate moved. When the predicate is a number (failing tests, a latency, a pixel diff), also keep it as a live chart that you rewrite each iteration (the **berth-artifacts** skill, a `berth.chart` line with `better` set), so the operator sees the trend at a glance. Outside berth, put the iteration table in the reply.
6. Before you declare the predicate met, spawn a fresh-context verification subagent (role `verification`, model and `effort` per the Subagents section of `~/.claude/skills/shipit/SKILL.md`). Give it the predicate and the result, and tell it to "report gaps, not style preferences". A gap it proves means the predicate is not met, so keep going.
7. Stop when the predicate is met and the verifier found no gap. A plateau is not a stop, so keep going and pivot your approach to push past it. Surface a genuine dead end rather than spinning, and never relax the predicate to declare victory.

**Reply:** the exit condition, iterations run, what landed, what was discarded, final predicate state. Link the trail and the predicate chart.
