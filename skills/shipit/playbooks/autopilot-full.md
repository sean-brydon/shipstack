### Autopilot-full

**You own the verdicts, never the PRs. One owner carries each PR from build to merge, and nothing merges until your swarm, which never wrote the code, has proven the code that lands.**

A verdict covers one patch and green CI covers one head. Step 4 runs a full swarm once, and again only for a major change. The patch-id rule in `~/.claude/skills/shipit/playbooks/shipping.md` can carry a lane's result, and every new head needs its own green CI.

A full-autonomy run assumes Claude Code's auto mode or a permission allowlist. The grant covers merging the queue's PRs. Force-pushes to shared branches, deploys, data deletion, messages to customers, and publishing still pause for the operator.

1. **The operator's gates come first.** The grant covers only the queue's items, so items the operator names as theirs and PRs outside the queue stop at merge-ready. A request to state the plan is not a go.
2. **Spawn one owner per PR, and keep its work where a replacement can find it.** The forge is GitHub through `gh`. Never require Graphite (`gt`). Each owner builds, opens its PR per `~/.claude/skills/shipit/playbooks/opening-a-pr.md`, proves the change on the real artifact, babysits to green per `~/.claude/skills/shipit/playbooks/babysit.md`, and merges once steps 4 and 5 clear it. When berth is available, each owner is a berth task off trunk (`berthd task new <loc>/<pr-slug> --base <trunk> --agent claude --prompt "<brief>"`, or the `berth_task_new` tool), with its own worktree, port, and env, and it reports back with a `<berth-notification>`. Read the **berth-orchestrate** skill first. Without berth, each owner is an Agent tool subagent with `isolation: "worktree"`, running in the background.

   Push the branch early so CI runs on it alongside the work. Open the PR only once the proof pack (`~/.claude/skills/shipit/references/proof-pack.md`) exists. The code is ready only after the cleanup pass (`/simplify`) and the **no-comments** pass (read and follow `~/.claude/skills/no-comments/SKILL.md`), so the full swarm runs on finished code. Then bring the branch up to current trunk (`git merge origin/<trunk>`) and report the code-ready head before self-proof, so verification runs on the base the patch lands on. Report every later head, and merge-ready once self-proof, CI, and babysit are done. Fix rounds stay on that base unless trunk conflicts or breaks CI, because each trunk update restarts CI. Run the repo's checks for the touched paths on the committed head before the code-ready push and before a later push that needs a verifier.

   Assume the owner's session dies. Soon after starting, push and start a decision trail in the program store (`~/.claude/shipit/autopilot/<program-slug>/`) per the **show-me-your-work** skill, then push after every unit worth keeping. Whoever spawns a subagent records its id (the berth session name, or the Agent tool's agent id), state, and a stuck-after runtime from past runs of its kind in that store, so the root can probe it if the parent dies. Update your branch from trunk with `git merge origin/<trunk>` and a plain push, because auto mode blocks force pushes by default. Rebase and force-push only your own branch, with `--force-with-lease` pinned to the SHA you last pushed or took over. If auto mode denies it, stop and report to the root. Don't retry. On any push you did not make, stop and report to the root.
3. **Run owners in parallel off trunk, never stacked,** so each PR lands on its own and none can merge into a branch that already merged. At most 5 owners run at once (the router's cap, or the user's). Queue the rest and start the next as one merges.
4. **Swarm-verify once.** A full swarm runs once, at the code-ready head. Another full swarm runs only for new behavior, a redesign, or a large new diff. A trunk update, a merge-conflict resolution, or a minor fix gets a single verifier at the new head. Fan out independent verifiers at the code-ready SHA per the **swarm** skill, on the `swarm workers` model. They re-run the gates, prove the load-bearing behavior live on the real surface (a page through the **berth-browser** and **berth-visual-diff** skills in the PR's worktree, or the **claude-in-chrome** skill without berth; a CLI or TUI through Bash or tmux; or a named driver), and audit the diff. Lanes that share one worktree each use their own browser tab (`--tab lane-<n>` on every `berthd browser` command). The verdict is not clean without the live lane, or before you audit the merge-ready report's receipts, because no lane trusts a claim it has not checked.

   Send every proven finding, whatever a lane labeled it, to the owner in one fix-forward, with a red test across every site with the same defect. On berth, that is one `berthd session send <owner> "…"` (or a fresh owner per the fresh-subagent rule in `~/.claude/skills/shipit/SKILL.md`). A defect trunk shows without the PR is recorded against trunk and does not gate the PR, but one the PR copies or newly reaches is the PR's own. Never push a fix yourself, because each branch has one writer. Replace a stuck owner instead.
5. **The owner merges only what you verified, tested on the trunk it lands on.** Green CI alone never authorizes a merge. Once the swarm's lanes have started, merge prep merges current trunk into the branch (`git merge origin/<trunk>`), reports the new head, and waits for green CI.

   Right before merging, fetch trunk and ask whether its changes can affect the patch, because updating for every trunk move never ends. Update from trunk and wait for CI when the code that would land was never tested, as with a conflict, a file both sides changed, or a change to which checks run for the PR. A lockfile both sides changed needs no update when a frozen install passes on the merge result and the packages the PR changes resolve there as on the head, because that install tests the lockfile that would land, and a failing install means the update must repair it. When trunk changed a caller of the patch or something the patch depends on, such as code it calls or a dependency version, run the patch's checks on the merge result and merge on a pass. Otherwise merge with `gh pr merge <pr> --squash`, after reading its base (`gh pr view <pr> --json baseRefName`) as trunk. Read the PR back (`gh pr view <pr> --json state,mergedAt,baseRefName`) to confirm it reads merged into trunk. If trunk would force a third update past merge prep, hold and report to the root, which sequences the colliding work.
6. **Run the root layer.** Anything that loosens a gate, such as a raised budget or an allowlist entry, needs a verifier's proof and then your fresh countersign, because the owner is the one who wants green. Under a grant that covers approvals, that countersign is the approval, and the owner's record of it points at your countersign for a lane to check. A disabled or soft-failed check always comes out, because it stops guarding every case. Never give or bypass an approval the forge enforces, because no countersign covers it.

   On the operator's go, arm `/loop 1h` to audit until no delegated work is left, because long runs drift and agents stall silently. Each tick re-reads this playbook from disk (`~/.claude/skills/shipit/playbooks/autopilot-full.md`) and fixes drift, such as an unreported head or an unrecorded agent, by having its owner record it, because drift is a gap in the record, not a stall. It probes every agent, down to the leaf lanes, and judges each by its side effects (pushes, trail rows, ledger rows, `berthd sessions --json` state), because status text and summaries can hide a stuck child. An agent is stuck when it errors, cannot start turns, or shows nothing new past its stuck-after runtime, and so is an owner that has neither pushed nor written a trail row by the first tick. One waiting on you or the operator is not stuck, so answer it if it waits on you, and tell the operator if it waits on them. Never answer for the operator. Replace a stuck agent at once, without waiting for its stop to land (`berthd session kill NAME`, or `TaskStop` for a local subagent, then a fresh owner with consolidated scope). A tick that changed something for the operator ends by catching them up per the **ketchup** skill, and one that changed nothing stays quiet.
7. **Stand down at once on the operator's stop.** A hold reaches every owner as a zero-writes order. Each reports where it stands and keeps its brief until the operator releases it.

**Evidence.** Keep one program table, one row per PR: PR link, owner (berth session or agent id), head SHA, CI, swarm verdict and the SHA it covers, lanes passed, countersigns, merged state as read back. Make it a table artifact you rewrite each tick (the **berth-artifacts** skill, a CSV with a `status` column; outside berth, the `Artifact` tool), with the commands its columns come from. Each live lane's screenshots are linked from its verdict.

**Reply:** catch the operator up per the **ketchup** skill, covering each PR's state and verdict, what merged, countersigns and why, and open operator gates, with links to each PR, the program table, and the trails.
